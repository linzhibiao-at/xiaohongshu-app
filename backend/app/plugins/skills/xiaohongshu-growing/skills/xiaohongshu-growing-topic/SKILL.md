# 选题

## 目标

产出 **15-17 条可直接进入排期的选题**，每条都说明：
为什么选它（数据）、靠什么赢（结构）、需要什么素材（成本）。

选题不是想创意，是在"有需求的缝隙"里下注。

## 命令序列

```bash
# 命令都在 growing 根目录（有 SKILL.md 那层）执行
# 生成池子（默认每支柱 3 条）
python3 scripts/growing_cli.py topic pool --lane 母婴育儿 --per-pillar 3

# 避开已发过的题目（传一个 JSON 数组文件）
echo '["之前发过的标题1","之前发过的标题2"]' > /tmp/sent.json
python3 scripts/growing_cli.py topic pool --lane 母婴育儿 --exclude-file /tmp/sent.json
```

## 怎么读输出

| 字段 | 含义 | 怎么用 |
|---|---|---|
| `pillar` | 内容支柱 | 排期要覆盖 ≥4 个支柱，避免单押 |
| `template` | 标题骨架类型（清单体/避坑体/对照体/结果体/身份体/场景体/预算体/流程体） | 决定正文结构，见 xiaohongshu-growing-copy |
| `title` | 生成的可用户标题 | 不要直接发，必须改写成用户自己的语气 |
| `search_keyword` | 对应的搜索词 | 用于验证需求：该词样本量与中位赞 |
| `competition.pillar_notes` | 该支柱已有样本数 | 越多说明供给越充分，越难出头 |
| `competition.pillar_median_liked` | 该支柱中位赞 | 是这条选题的"及格线"参考 |
| `collect_intent` | 收藏动机 high/mid/low | high 优先，长尾价值最高 |
| `material` | 需要的素材 | 用户做不到的直接剔除 |
| `risk` | 风险提示 | 逐条处理，不要忽略 |
| `evidence.hook_patterns` | 该赛道高频钩子 | 说明为什么这个模板在赛道内有效 |

## 筛选原则（挑 15-17 条进排期）

按顺序过滤：

1. **素材可得**：`material` 里的东西用户本周真能拿到吗？拿不到就删。
2. **收藏动机**：至少 60% 是 `high`。全是 `mid` 说明内容偏"看过就走"。
3. **支柱覆盖**：≥4 个支柱，每个支柱 ≥2 条（少于 2 条无法验证该支柱）。
4. **搜索型占比**：≥3 条选题的关键词是用户会主动搜的词（如"宝宝辅食 6个月"）。
5. **钩子分散**：不要 8 条都是清单体，至少 3 种不同模板。
6. **竞争度**：同一支柱内，优先 `pillar_notes` 低但 `pillar_median_liked` 高的（供给少 + 有需求 = 缝隙）。

## 给用户的表达方式

不要直接扔 17 条标题。按"支柱"分组，每组给："为什么做这个支柱 + 3 条选题 + 该支柱的及格线"。

```markdown
## 选题矩阵（17 条，覆盖 6 个支柱）

| 支柱 | 条数 | 该支柱中位赞（及格线） | 主用模板 |
|---|---|---|---|
| 喂养辅食 | 3 | 3200 | 清单体 ×2、流程体 ×1 |
| ... | | | |

### 喂养辅食（3 条）
> 这个支柱供给充足（样本 42 条），但收藏赞比 0.62，属于"存下来照着做"的类型，
> 适合做系列。及格线 3200 赞。

| # | 标题（待改写） | 模板 | 收藏动机 | 需要的素材 | 竞争度 |
|---|---|---|---|---|---|
| T01 | 6-12月龄辅食清单｜12个真能吃进去的搭配 | 清单体 | high | 12 组实际餐盘照片 | 中（42 篇） |
```

## 单条选题的 5 个判断标准

交付前对每条自检，任何一条不过就换：

| 标准 | 自检问题 |
|---|---|
| 有需求 | 对应的搜索词在站内有没有 ≥20 条样本？ |
| 有缝隙 | 同支柱里有没有人做过一模一样的？做了多少次？ |
| 能收藏 | 读者看完有"得存下来"的理由吗（清单/参数/步骤）？ |
| 能拍 | 本周内能拿到素材吗？ |
| 能系列 | 这条能拆成 3 篇吗？不能的话它只是单点，不是支柱 |

## 常见错误

- **全是清单体**：清单体容易起量但同质化最快，必须混入避坑/对照/流程。
- **忽略 material**：用户没孩子却推荐"宝宝辅食"，整条作废。
- **把生成的标题直接发**：`title` 是结构示例，必须按用户语气重写（见 xiaohongshu-growing-copy）。
- **支柱过多**：6 个支柱各 3 条看起来丰富，实际每个支柱只测了 1-2 次，验证不了。
  首月建议 **4-5 个支柱**，下月再扩。
- **不看 competition**：选了样本 200 条、中位赞 200 的支柱，做到最好也拿不到量。
