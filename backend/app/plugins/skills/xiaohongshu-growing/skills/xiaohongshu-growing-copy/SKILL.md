# 文案

## 目标

写出 **能被收藏** 的笔记，而不是被点赞的笔记。
判断标准：读者看完有没有"得存下来/想回复"的冲动。

## 流程（不可跳步）

```bash
# 命令都在 growing 根目录（有 SKILL.md 那层）执行
# 1. 取写作骨架
python3 scripts/growing_cli.py copy brief --lane 母婴育儿 --pillar 喂养辅食 --template 清单体

# 2. 你写稿，落文件（长文本不要内联到命令行）
#    标题 → /tmp/xhs_title.txt
#    正文 → /tmp/xhs_body.txt

# 3. 机器校验（必须 ok: true）
python3 scripts/growing_cli.py copy check \
  --title-file /tmp/xhs_title.txt \
  --body-file /tmp/xhs_body.txt \
  --tags 辅食 育儿 母婴

# 4. 发布前诊断（评分卡）
python3 scripts/growing_cli.py copy audit --lane 母婴育儿 \
  --draft-dir data/exports/drafts \
  --cover data/exports/covers/01_cover.png \
  --goal 爆文流量
```

`copy brief` 返回 `hook`（结构）、`must_include`（必须出现的信息）、`avoid`（禁止项）、
`cta`（互动钩子方向）。写之前先读一遍，不要凭感觉写。

## 标题：20 字上限，UTF-16 计长

emoji 占 2 个字符，`copy check` 会算。5 种公式：

| 公式 | 结构 | 适配支柱 | 例 |
|---|---|---|---|
| 数字清单 | 数字 + 对象 + 承诺 | 用品避坑、区域清单、收纳 | `6-12月龄辅食清单｜12个真吃进去的` |
| 避坑否定 | 阻止 + 代价 | 用品避坑、装修避坑、排队避坑 | `婴儿车别乱买，这5个坑我替你踩了` |
| 对照取舍 | A vs B + 判断标准 | 对照体类 | `贵价和平价辅食机，我最后留了后者` |
| 结果前置 | 时间 + 结果 | 空间改造、成长发育 | `30天把出租屋儿童房改到能住` |
| 身份背书 | 身份 + 只推荐 N 个 | 单店测评、绘本共读 | `二胎妈只回购这4样洗护` |

标题硬规则：
- 必须含数字或明确结果（否则点击率普遍偏低）
- 必须有一个分隔符 `｜` 或 `，` 切分两个信息块
- 不用"最好/第一/100%/绝对"（`copy check` 会告警）
- 不用问句做标题除非答案反常识

## 正文：四段结构

```
第一段（钩子）  1-2 行，直接给结论或代价，不铺垫、不自我介绍
第二段（主体）  分点或分段，每点：做法 + 一个具体数字/条件
第三段（边界）  什么情况不适用 / 我踩过的错，这一段的收藏价值最高
第四段（互动）  一个只需一句话就能回答的问题
```

硬规则：
- 总长 300-800 字最佳；<60 字缺支撑，>1000 字超上限
- 每段 ≤4 行（手机阅读密度）
- 至少出现 3 个具体数字（价格/数量/时长/月龄）
- 结尾必须有 CTA，且是"二选一"或"报情况"型，不要"欢迎交流"
- 正文不写站外联系方式（`copy check` 会告警）

## 话题标签：3-8 个，三层配比

| 层 | 作用 | 数量 | 例（母婴） |
|---|---|---|---|
| 赛道大词 | 打标签、进大池子 | 1-2 | `#母婴` `#育儿` |
| 场景词 | 命中搜索 | 2-4 | `#宝宝辅食` `#6个月辅食` |
| 人群/长尾词 | 精准触达 | 1-2 | `#新手妈妈` `#职场妈妈` |

- 从 `benchmark author` 的 `tag_usage` 里取高频词，比自己编更准。
- 不要堆 10 个以上的热门大词，会显得堆砌且分散标签。

## 发布前诊断：机器分与待补判

`copy audit` 跑的是本技能自带的评分卡，五维 100 分的权重在
`references/rednote-rubrics.md`（相对 growing 根目录）。但它只对能从文字确定的部分给分。

看三个数：

| 字段 | 含义 |
|---|---|
| `machine_score / machine_max` | 机器能判的分数，例如 46.5/66。**这不是总分** |
| `pending_max` | 机器判不了的分数，例如 34（封面 25 + 标题封面一致 2 + 对标新角度 4 + 趋势契合 3）|
| `dimensions[].subs[].evidence` | 每个得分的依据，能指回草稿里的具体词 |

必须做的事：

1. 真的去看 `--cover` 那张图，判封面 5 个子维度（承诺清晰、缩略图可读、视觉对比、好奇冲突、平台原生感）。
2. 按 `references/comparison-protocol.md` 搜同类笔记，判「对比同类的新角度」。
3. 把两边的分数相加才给总分，并写清楚信心等级。

直接拿 `machine_score` 当总分汇报是错的，会把「封面根本没看」这件事藏起来。

`edits` 是按丢分大小排的优先修改清单，已经带上具体改法。`--goal` 不改权重，
只把该目标最相关的子维度提到前面：

- `IP增长`：IP 关联、关注理由、结尾记忆点
- `产品转化`：痛点强度、行动价值、评论触发
- `爆文流量`：搜索意图词、点击钩子、首卡钩子

## 输出模板

交付给用户时给"可直接粘贴"的成品，并附校验结论：

```markdown
## 标题（12 字符 / 上限 20）
6-12月龄辅食清单｜12个真吃进去的

## 正文
（完整正文）

## 话题
#宝宝辅食 #6个月辅食 #新手妈妈

## 校验
- 标题：通过（12/20 字符，含数字+分隔符）
- 正文：通过（486 字，4 段，含 5 个数字，有 CTA）
- 话题：通过（3 个，覆盖场景+人群）
- 提醒：「第一次吃蛋黄要观察 3 天」属于专业建议，建议标注来源

## 封面文案（图上文字，≤12 字）
辅食清单 / 12 个搭配
```

## 常见错误

- **形容词代替信息**："超级好用" → 改成"用了 8 个月没坏，洗一次 2 分钟"
- **开头自我介绍**：正文第一句不要写"大家好我是 xx"，人设篇除外
- **CTA 太泛**："欢迎评论区交流" → 改成"你家是 6 个月还是 8 个月开始的？"
- **标题塞满关键词**：`宝宝辅食6个月辅食清单宝宝辅食推荐` 会被判定堆砌
- **忽略 must_include**：brief 列的信息点缺一个，收藏动机就掉一档

## 封面出图

封面文案定稿后，用 `promotion-poster-creator/scripts/do_text.py` 把它叠到无字底图上，
产出 3:4 竖版 PNG（如 768×1024），路径传给 `copy audit --cover`。
命令与其参数见主 `SKILL.md` 的「封面与卡片产出」。图文卡片同理，用 `assets/presets/rednote/` 的预设。
