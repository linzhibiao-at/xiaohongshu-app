# 30 天排期

## 目标

把选题变成 **有节奏、能验证、可调整** 的发布计划。
排期的本质是设计实验：每个阶段验证一个假设，而不是平均分配内容。

## 命令序列

```bash
# 命令都在 growing 根目录（有 SKILL.md 那层）执行
# 1. 生成 + 落库 + 导出方案 HTML（落工程根 reports/）
python3 scripts/growing_cli.py plan build --lane 母婴育儿 --start 2026-11-11 --days 30 --save --export html

# 2. 查看接下来要发的三条（进入写稿流程）
python3 scripts/growing_cli.py plan next --plan-id <id> --limit 3

# 3. 发布后标记状态（item_id 来自 plan show）
python3 scripts/growing_cli.py plan mark --item-id 12 --status published --feed-id <note_id>

# 4. 完成度
python3 scripts/growing_cli.py plan progress --plan-id <id>

# 5. 有几天没发出去，整体顺延
python3 scripts/growing_cli.py plan shift --plan-id <id> --from-day 8 --delta 2
```

Agent 自定选题时可先写 JSON 再传入：
```bash
python3 scripts/growing_cli.py plan build --lane 母婴育儿 --topics-file /tmp/topics.json --save --export html
```

`--export` 可选 `html` / `md` / `csv`：`html` 写工程根 `reports/`（交付件），
`md` / `csv` 写 `data/exports/`（数据档，给表格工具用）。

## 四个阶段的设计意图

| 阶段 | 天数 | 篇数 | 验证什么 | 关键动作 |
|---|---|---|---|---|
| 立人设 | D1-7 | 3 | 账号标签是否被正确识别 | 首篇人设，其余各支柱 1 篇，封面风格统一 |
| 测选题 | D8-14 | 5 | 哪类选题能拿到流量 | 5 个不同钩子各 1 篇，保留数据最好的 2 个方向 |
| 放大 | D15-21 | 4 | 已验证方向能否做成系列 | 2 个方向各 2 篇，加互动钩子 |
| 沉淀 | D22-30 | 5 | 能否形成搜索长尾 | 清单/攻略型 + 首月复盘 + 下月选题池 |

总计 17 篇。**不要**在前两周追求"每篇都爆"，测选题阶段的目标是拿到分布数据。

## 产能匹配（必须核对）

| 用户每周可投入 | 建议篇数/周 | 调整方式 |
|---|---|---|
| <3 小时 | 2-3 | 删掉视频，只做图文；`--days` 可拉到 45 天 |
| 3-8 小时 | 4-5 | 默认排期即可 |
| >8 小时 | 5-7 | 增加视频比例，缩短到 21 天验证周期 |

用户时间不够而排期给了 17 篇，直接会导致中途断更。**断更比少发伤害更大**，
必须按真实产能重排。

## 怎么读输出

| 字段 | 说明 |
|---|---|
| `summary.total_posts` | 总篇数，默认 17 |
| `summary.by_phase` | 各阶段篇数，用来核对节奏 |
| `summary.by_pillar` | 支柱分布，某支柱只有 1 篇说明验证不了 |
| `summary.by_type` | 图文/视频比例 |
| `checks` | 排期自检结果，含"同天发布""连续同支柱""首周不足 3 篇" |
| `items[].publish_at` | 建议发布时间（赛道经验值，需按实际数据回流修正） |
| `items[].topic_id` | 关联的选题池 ID，方便回查依据 |

`checks` 里出现"同天发布"或"缺少人设篇"是硬问题，必须修好再交付。

## 交付物

1. 排期方案文件路径：`reports/plan-<赛道>-<日期>.html`（工程根，可直接打开）
2. 每周目标（一句话）
3. **首周 3 条的具体执行清单**：标题、需要的素材、拍摄要点、发布时间

## 输出模板

```markdown
## 30 天排期总览
- 周期：2026-11-11 ~ 2026-12-10，共 17 篇
- 阶段：立人设 3 / 测选题 5 / 放大 4 / 沉淀 5
- 支柱：喂养辅食 4、用品避坑 3、亲子陪伴 3、空间改造 3、绘本共读 2、人设 2
- 文件：reports/plan-母婴育儿-2026-11-11.html

## 每周目标
| 周 | 天数 | 目标 | 判断标准 |
|---|---|---|---|
| W1 | D1-7 | 让算法识别账号标签 | 3 篇都进入推荐池（播放 >500） |
| W2 | D8-14 | 找到能起量的方向 | 至少 1 篇 > 赛道中位赞 |
| W3 | D15-21 | 把胜出方向做成系列 | 同方向 2 篇中位赞不低于首篇 70% |
| W4 | D22-30 | 拉搜索长尾 | 出现收藏赞比 >0.8 的内容 |

## 首周执行清单
### D1（11-11 周二 21:00）人设篇
- 标题：...
- 素材：...
- 拍摄要点：...
- 目标：让评论区出现"我也是"的共鸣

### D3 / D6 ...

## 自检
- [x] 无同天发布
- [x] 含人设篇
- [x] 首周 3 篇
- [ ] 用户产能已确认（每周 x 小时 → x 篇）
```

## 常见错误

- **按"每天一篇"排**：冷启动期质量 > 数量，日更但每篇都平，等于没数据。
- **支柱全押一个**：17 篇全做辅食，验证了一个点，损失了 5 个可能更好的方向。
- **顺序错**：先做放大再测选题，等于把没验证的方向批量生产。
- **发布时段写死**：`publish_at` 是经验值，必须用自己账号的实际数据回流修正。
- **断更后不重排**：停更 3 天却继续按原计划发，节奏全乱，应该用 `plan shift`。
